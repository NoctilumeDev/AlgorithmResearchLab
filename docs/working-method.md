# 研究工作法

状态：准备阶段的方法约定；研究实验未开始。

方法来源：[VeriTrail 证据反馈工作法](https://github.com/NoctilumeDev/VeriTrail/blob/d794731d2402efe98ff572a38cfcf898c22352d7/docs/working-method.md)。这里复用适用原则，不继承该项目的状态、实现资格、具体门禁矩阵或工具能力。

## 1. 外层：决定本轮研究什么

1. 核对当前代码、文档、数据、模型、计划、运行与结果的身份；已经有远端或发行物时也核对相应坐标。
2. 区分已经支持的事实、当前候选假设、缺失证据、反例和延期能力。
3. 检查新观察是否破坏原来的前提；先保留异常，再区分算法、模型、数据、评估、环境和执行设施中的问题。
4. 只选择证据支持的最小下一步。路线图与版本编号不替代这个判断。
5. 新证据形成后，同步结论、边界与项目状态，再返回本轮问题选择。

## 2. 内层：决定结论凭什么成立

验证性实验在运行前固定：问题、基线、主要变量或组合矩阵、输入与环境、指标定义、误差口径、允许波动、重复方案、停止条件和证据要求。

探索性实验可以寻找问题与假设，记录为探索。拟正式支撑的结论需要相应验证；由探索产生的标准不能回写成旧实验的预期。

按当前层需要建立检查链：

```text
明确身份与计划
  -> 检查算法实现及评估路径
  -> 取得计划要求的实验或推导证据
  -> 保留原始观察与中止事实
  -> 独立核对结果、归因与适用范围
  -> 发布有边界的结论
  -> 返回外层问题选择
```

涉及提交、合入、发行或工具集成时，另行声明对应的完整性、兼容与读回要求。不要把验迹的浏览器、双 Python 或发行门机械复制成每个算法实验的固定成本。

## 3. 事实、判据与解释分别记录

- 运行记录保存实际发生的事实及来源。
- 评估规则保存指标、判据与版本。
- 研究解释说明证据支持什么、不能判断什么、结论在哪些条件下适用。
- 代码正确、运行完整、假设受支持、结论可推广与下一步获准，分别判断。

测试是限定范围的证据。Agent 互评可以发现疑点，不能自动成为独立复现或目标有效性的认证。

## 4. 控制变量与比较

- 单变量实验用于检查特定变化；显式组合矩阵用于检查交互。
- 预注册覆盖范围先于随机扰动；随机运行不能补写成缺失组合已经覆盖。
- 数据生成、观测采样、模型初始化与运行顺序的随机性分别记录。
- 固定种子提供复现坐标；跨随机条件的稳定性需要自己的重复方案。
- 性能结论说明实现、资源与测量开销；算法资源和评估设施开销分别记录。
- 重要结论使用适用的对照、负对照、消融或独立复算；具体设计由当前问题决定。

## 5. 评估器与算法的信息边界

模拟环境可以定义 U，由独立评估路径读取。被研究算法只消费计划允许的观测，不能通过标签、调参、状态对象或选样步骤偷看 U。

效用知情的 oracle 可以作为明确标记的参照，不能与被研究算法的访问边界混用。模拟生成器应允许代理有效、有限误差仍可接受以及失真等不同情况，避免直接写入期待结论。

## 6. 首败与不确定性

区分假设被反驳、实现错误、资源中止、观测污染、缺证据和不可识别。后继成功不删除或解释首败。

出现反例后先保存现场与身份，再归层。语义前提需要修改时，只修改受影响的最小边界，形成新版本并取得新证据。

同一输出、摘要或相同代码不自动继承另一次运行的资格。报告支持、反驳、怀疑、尚未观察到或无法判断时，说明对应证据强度。

## 7. 证据保留与恢复

后续实验至少能追溯到代码版本、计划版本、数据或生成器身份、参数、随机性、环境、原始结果和分析规则。哈希用于绑定字节，不证明来源真实性或数学真理。

原始产物按独立运行身份保留，派生图表与报告能够从来源重新核对。修改数据、规则或基线后重新检查旧结论的适用性。

模型切换或上下文压缩后，先读取 README、AGENTS、范围与方法，再回到真实文件及证据恢复状态；不从摘要中的“下一步”自动开工。
