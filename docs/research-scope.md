# 研究范围与命名

记录日期：2026-10-06。状态：准备阶段；研究未开始。

## 1. 命名约定

| 对象 | 名称 |
| --- | --- |
| 仓库 | AlgorithmResearchLab / 算法研究实验室 |
| 核心研究 | 漂移算法 / Drift Algorithm |
| 首选实验语言 | Python |

名称作为长期引用约定。具体数学定义、输入输出、适用条件和算法机制由后续研究建立，修改时保留版本与理由。

“漂移算法”目前是核心算法研究的名称，没有对应已实现的例程、软件包或既定检测器。

## 2. 研究问题

通过大数据算法和推荐算法两个可控实验面，研究有限观测与反馈优化过程中，代理指标对既定目标的决策有效性如何变化，以及变化的机制、识别边界与可能的干预方法。

关注目标与代理定义保持不变的情况。定义固定仍允许其取值随着行动和环境变化。

静默情形是重点观察对象：代理指标稳定或改善，而对目标的决策有效性下降。它是待研究的情形，不能预先写成必然结果。

## 3. 概念草图

| 符号 | 工作含义 | 待明确的边界 |
| --- | --- | --- |
| U | 既定目标或模拟中设定的效用 | 定义、适用人群、时间范围及评估访问权 |
| P | 用于优化或选择的代理指标 | 定义、单位、方向、聚合与决策规则 |
| O | 观测过程 | 采样、摘要、近似、曝光及数据选择 |
| A | 优化或决策算法 | 可见信息、可行动域与计算预算 |
| E | 环境状态 | 外生变化与行动诱导变化的区分 |
| F | 反馈规则 | 行动怎样影响后续状态与数据 |

这些符号帮助组织问题，目前不构成冻结的数学模型、类型系统或公共 Schema。

代理有效性关注：在声明的环境、观测与决策范围内，依据 P 选择行动是否仍能支持 U。它可能需要一组条件，不能提前压成一个相关系数或固定标量。

目标改变、代理有效性变化属于变化对象；优化器诱导、外部环境变化等属于成因。两者不作为互斥分类。

## 4. 观察路径

1. **分别观察：** 建立具体大数据算法与推荐算法的行为、性质、误差和边界。
2. **改变条件：** 检查规模、分布、稀疏性、观测预算、目标选择等变化怎样影响已有结论。
3. **耦合观察：** 检查有限观测、决策与反馈相互作用产生的行为。
4. **抽象提炼：** 在多个受控世界和具体算法之间验证候选共同机制，寻找不成立的条件。

以上是观察路径，不是固定施工顺序。V1/V2/V3 可以根据证据调整；单体反例可以提前引出抽象问题，耦合反例也可以要求补充单体研究。

观察到现象、解释成因、取得跨设置抽象以及实现有效干预，分别需要自己的证据。

## 5. 必须保留的区分

- 训练目标、选择或重排规则、评测指标分别记录；改变报告指标不自动代表改变了优化目标。
- P 未被充分优化、U 饱和或目标取舍，不自动认定为代理失效。
- 静态错配与随条件或时间变化的有效性损失分别检查；漂移判据需要明确此前的有效范围。
- 代理数值估计误差、代理与目标的偏离、优化误差分别定义，不混用百分比与分母。
- 相关系数变化只是一种观察；行动收益、选择范围和用户构成等也需进入判定。
- “未观察到影响”说明实验范围与分辨能力；不自动证明没有影响。
- 模拟中的 U 是设定的评估依据；现实中的效用与代表性需要额外证据或可检验假设。
- 缺少目标相关信息时，允许无法识别成为正式结论。

## 6. 范围与成果

研究成果可以是具体算法性质、误差传播、受支持的机制、被反驳的直觉、失效边界、不可识别性，或在证据需要下形成的新算法。

“优化越强越有害”“近似必然放大失真”“反馈最终收敛”“所有漂移可检测”均不得作为既定结论或验收目标。

最小设施服务实验。部署、运维、中间件、学术投稿流水线与通用 Agent 平台不属于当前范围。

VeriTrail 与 FlowKernel 的后续连接是研究设想，尚无依赖、接口或已验证的组合能力。

## 7. 进入与停止条件

准备阶段结束后，等待用户明确启动研究；再根据当时证据选择首个最小问题与计划。

首个计划需要给出有限的算法、分布、资源和反馈范围，明确需要取得的证据与停止条件。探索与验证可以交错，但旧运行及其判定条件继续保留。

在声明范围内取得支持、反驳或不可识别的明确结论，即可形成有边界的闭合。抽出统一机制、实现检测或干预算法，以及一定完成三个版本，均不作为默认停止前提。
